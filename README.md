Docker file explanationhbv

1. FROM openjdk:11
Purpose:

This line specifies the base image for the Docker image.

openjdk:11 is an official Docker image that comes pre-installed with OpenJDK 11 (Java Development Kit).

Why It’s Needed:

Java applications require the JDK or JRE to run.

By using this base image, you don’t need to manually install Java inside the container.

Example:
docker pull openjdk:11


This pulls the OpenJDK 11 image, which will serve as the starting point for your app.

2. ARG JAR_FILE=target/*.jar
Purpose:

ARG is used to define a build-time variable.

Here, JAR_FILE is a variable representing the path to the application JAR file.

Default Value:

target/*.jar means:

Inside the target/ directory, take any JAR file generated by your build tool (usually Maven or Gradle).

Maven builds typically place compiled JAR files in the target/ directory.

Example:

If you built a Maven project:

mvn clean package


Maven will create a JAR like:

target/finance-app-1.0.0.jar


ARG JAR_FILE=target/*.jar will match this JAR.

3. COPY ${JAR_FILE} app.jar
Purpose:

Copies the compiled JAR file from your host machine into the Docker image.

${JAR_FILE} uses the variable declared above.

The file is copied and renamed to app.jar inside the container.

Syntax:
COPY <source> <destination>


Source (${JAR_FILE}):

Host machine path (e.g., target/finance-app-1.0.0.jar).

Destination (app.jar):

Inside the Docker image, placed in the root directory /.

Example Flow:

Before copying:

Host machine:
target/finance-app-1.0.0.jar


After copying:

Inside container:
/app.jar

4. ENTRYPOINT ["java","-jar","/app.jar"]
Purpose:

Defines the default executable command that runs when a container starts.

This command tells Docker to:

Run java command.

Use the -jar option to execute a JAR file.

Run the JAR file located at /app.jar.

Exec Form Explanation:

Written in exec form (["java","-jar","/app.jar"]) rather than shell form (java -jar /app.jar).

Benefits of exec form:

Better signal handling (important for PID 1).

Prevents unwanted shell behavior.

Safer and more predictable in production containers.
